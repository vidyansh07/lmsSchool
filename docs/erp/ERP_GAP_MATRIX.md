# ERP gap matrix

What exists today, what the ERP brief requires, and how each gap is closed.
Measured from the code on 15 September 2026 (branch `feat/erp-platform`, from
`feat/erp-foundation` at e39a53e). Nothing in the "Existing" column is a
guess; every row names the file that proves it.

Legend for **Disposition**: **Reuse** as-is · **Extend** existing code ·
**New** module · **Change** existing behaviour · **Remove** nothing is removed
in this programme (D-019: educational history is never deleted).

## What is deliberately not built

| Item | Why |
| --- | --- |
| DEPARTMENT scope | No department entity exists in the product; the owner's organisational unit is the centre (D-129). Adding departments changes the org model and needs the owner's call. Recorded as NOT_STARTED in the checklist. |
| JWT / token auth | Never (owner's standing rule; D-002). MFA and sessions are built on the session cookie. |
| Arbitrary automation code | Automations are rows evaluated by a fixed-vocabulary engine (ADR-13). |
| Dark mode | Declined twice (D-101). |
| A second audit system | Activity = work; audit = system/security. The audit-feed screen stays as the "activity review" the owner asked for on 14 September; the work engine is a different app (`work`). |
